# 对标账号分析要求（2026-11-11 用户确认）

用户要求：对标账号分析要补齐四件事，并与会话2参考视频分析去重。

## 1. 每个账号必须有首页截图

- 对每个 confirmed 对标账号，用 Edge 只读打开其抖音主页，截取**真实首页截图**（至少包含头像/昵称/简介/作品数/置顶或首屏作品卡）。
- 保存到 `research/benchmarks/<analysis_id>/accounts/<account_id>/profile.png`，并写 `profile.json`：`profile_url`、`captured_at`（Asia/Shanghai）、截图方式、视口尺寸、sha256、未能截图的账号及原因。
- 不得用占位图、旧图或他人截图冒充；打不开/需登录就标 `unavailable` 与具体原因，不用其他账号替代。

## 2. 每个账号必须有可点击的主页链接

- 每个账号条目都写 `profile_url`（`https://www.douyin.com/user/...`）与昵称，报告里用 Markdown 链接呈现，可点击跳转。
- 链接须实际核验（页面标题/昵称与账号一致）；无法确认标待核，不把搜索页当主页。

## 3. 最近视频趋势：只分析上次分析之后的新视频

- 窗口：**上一次对标分析截止时间 → 本次分析时刻**，按 Asia/Shanghai 冻结。
- 首次执行（无上次截止时间）：取该账号最近 90 天内、最多 20 条公开作品；不足如实记录；以后只取新增视频。
- 新增超过 20 条/账号时，取最近 20 条并记录被截断数量与原因。
- 分析口径与参考视频一致：真实发布时间、公开链接、点赞/评论原始显示值与精度、开头钩子、结构（开场/主体/收尾）、可迁移机制、不可照搬点、事实边界；不编口播、BGM、封面或 CTA。
- 保存 `accounts/<account_id>/videos.json`（逐条）与报告中的趋势小结（选题方向、形式、更新频率、互动变化）。没有新视频就写“零新增”，不得用旧视频顶替。

## 4. 最近视频的评论分析

- 对每条新增视频抽样可见评论，目标 30 条；记录采样顺序/时间、实际样本数、表情与低信息条数、判定依据。
- 归纳评论诉求、反对意见、常见疑问与可复用选题线索；样本不足标 partial，不推断整体观众。
- 保存 `accounts/<account_id>/comments.json` 与报告中账号级评论小结。
- 不得把评论样本写成“已证实投流/限流”，不得读取私信或客户身份信息。

## 5. 与会话2同步（避免重复分析）

- 每次分析输出 `research/benchmarks/<analysis_id>/sync-manifest.json`：`analysis_window`（上次截止→本次截止）、`accounts`（account_id/name/profile_url/profile.png/videos.json/comments.json）、`video_ids`、`generated_at`、方法、限制。
- 会话2 的 benchmark 20 条：直接引用会话1的 `videos.json` 分析结果与评论结果，**不再重复做对标账号视频的内容拆解和评论抽样**；批次数据里标 `content_analysis_ref`（指向会话1文件+video_id）。
- 会话2 仍负责批次层面的候选、去重、配额、点赞/评论显示值与排序；若会话1文件缺失或早于批次时间窗口，标 `reused_session1_analysis=false` 与缺口，不编造、不重复深拆。
- 会话1 只写 `data/benchmarks.json` 与 `research/benchmarks/`；会话2 只写 `batches/`，不互相覆盖。

## 6. 证据与边界

- 所有截图、链接、指标、评论都要有采集时间与来源；无法访问/需登录/页面打不开如实记录。
- 不绕过登录/验证码/技术保护，不读凭据或 Cookie，不发布/互动/投流。
- 报告与结构化文件写清已完成、未验证、缺口与下一步。
