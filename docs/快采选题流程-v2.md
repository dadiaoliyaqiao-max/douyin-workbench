# 会话2快采与精选深拆｜v2

## 用户确认与边界

2026-11-08，用户在`session2_fast_mode`选择“快采50候选，选中后深拆（推荐）”。本版替代“50条全部深拆后才选片”的默认方式；不降低来源真实性、六个自然月、15/20/15、去重、隐私与外部操作授权要求。总管采用终态回执触发，不进行持续巡检或自动目标续轮。

## 第一阶段：50条快采候选

1. 新一轮按[2026-11-09筛选更新](<参考视频筛选规则-20261109.md>)冻结分类窗口：非家居15条仅启动前72小时，对标20条/其他家居15条保留六个自然月。续接旧批不重置元数据；需要改用新规则须保留旧版另作修订。
2. 所有类别排除美食/吃播。非家居只搜72小时内，点赞→评论→日期降序；对标/其他家居继续近30天→90天→六个月搜索，评论→点赞→日期降序。不足不扩非家居窗口，不声称全平台最热。
3. 基础字段：作品ID、直达链接、账号/归属、分类、真实发布时间、采集时间、评论/点赞及原始显示精度、来源、主题短述。主题可以据公开文案转述，但不冒称已观察到视频脚本。
4. 评论先快速排雷：明显相对高赞且低信息主导的排除；证据不足标“待深核”，不能标完整合格。只存匿名必要信息。已有有效样本可复用，修解析错误不伪装新采样。
5. 不要求全部50条固定三点截图、完整结构拆解、封面和BGM追查；这些标“快采阶段未采集/待深拆”，而非谎称不存在或取得不到。
6. 交付分类排序的简短候选清单与基础自查结果。`candidate_stage_complete`只表示候选阶段完成，不等于旧版`valid`或`delivery_complete`。
7. 报告顶部必须给总体分析与建议、每条候选标题下必须写入选原因（分类配额/评论点赞依据/窗口/可迁移机制），见[参考视频报告要求](<参考视频报告要求-20261111.md>)。

## 第二阶段：用户选中后再深拆

- 用户指定作品ID，数量由用户决定，不强制5条或10条。
- 只对所选作品核实真实内容、必要评论、结构、文案和可取得素材；观察方式与局限明确。评论目标30，缺信息不能靠理由硬通过；不编口播、CTA或音乐。
- 2026-11-11起，**所有拆解视频必须**按[豆包文案提取规则](<豆包文案提取规则-20261111.md>)把公开视频链接发给豆包提取逐字稿，并把逐字稿纳入深拆分析（card/evidence/deep-check/handoff-input/report）。只发链接与最小指令，原始输出、元数据和比对修订分开保存，标注AI辅助未真人审核；豆包不可用或只给摘要时该作品深拆不得标完成，报blocked/partial，不擅自改用其他AI服务。逐字稿仅作结构/表达研究，不替代来源核验。
- 不强制机械三时点截图。已有可信证据复用；不足时按内容需要补证，异常有限重试，不能无限卡在同一作品。
- 总管一次集中验收；所选内容核验通过且记录用户确认后，才准备不可静默覆盖的选片/交接快照。未经确认不得换片或启动会话3。

## 与旧批次及CLI的关系

- 原v1批次及其未通过记录保留，不改窗口、配额、旧指标和真实采集时间，不把它回溯标成完整合格。
- 本次从原批次已有20条观察记录与30条候选生成独立v2快采视图，不重新浏览整轮，也不重新建批。
- 旧CLI仍按v1完整50条材料校验，不能拿快采视图冒充其通过。快采使用独立候选阶段自查。
- 用户选片后，按v2所选集合补齐相应验收与不可变交接支持；支持未完成或资料未核实前，不绕门槛让会话3开工。2026-11-09新增[单条原创交接校验](<v2单条原创交接.md>)，独立校验所选benchmark/home补核材料、用户确认、总管验收及素材哈希，返回带selected_reference_only作用域的三项开工状态；不修改旧批次状态，不额外开发采集框架。

## 执行节制

已有数据复用、一次打开尽量取齐基础信息；不反复重采、不为了提速乱并发、不反复重启连接。总管只在终态回执或用户主动查询时检查；问题一次性汇总。
