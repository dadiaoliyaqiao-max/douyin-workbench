# 参考视频报告要求（2026-11-11 用户确认，第二次修订）

适用：会话2「参考视频」的候选报告（如 `batches/<批次>/quick-pick-v3.md` 及其结构化视图），不改变原有筛选配额、窗口、去重与真实性规则。

## 0.1 自选分类（2026-11-11 用户新增）

- 用户直接提供的抖音视频（短链或长链），由会话2只读解析出作品ID后做**完整深拆**，并追加到参考视频报告，分类为 **【自选】**，编号从 **S01** 起。
- 自选视频**不计入** 15/20/15 配额，也不改变原批次窗口、排序与旧事实；报告需注明“自选为额外补充”。
- 与已有 50 条作品ID重复时：不重复建卡，直接标注“已在批次中（编号X）”，并把深拆结果并入该条。
- 报告版式仍按原表格：在末尾新增“自选（用户指定）”小节，列与原表一致，并保留“入选原因（简短）”列（写“用户自选”）。
- 深拆必须包含：全片结构观察、评论抽样、**豆包工作模式逐字稿**（`新工作任务→工作`）并纳入 card/evidence/deep-check/handoff-input；未取得逐字稿按 blocked/partial，不标完成。
- 结构化文件：`batches/<批次>/self-selected.json`（items 数组，含 video_id/url/code/category='自选'/cover/deep_dive_status/reason），供侧栏索引展示。

## 0.2 做原创剧本前置流程（2026-11-11 用户确认）

- 参考视频卡上的【做原创剧本】按拆解状态分两种：
  1. **未拆解**：点击弹出对话框“该视频还没有拆解，不能直接做原创剧本”，必须先拆解（结构＋评论＋豆包完整逐字稿）后才能做剧本；对话框可一键“先拆解这个视频”。
  2. **已拆解**：点击弹出对话框，让用户填写“本次做剧本的要求”；提交后把要求原文随任务交给会话2补核/会话3创作。未填写则按账号定位与参考机制创作。
- 要求文本≤2000字，绑定到操作ID：同一操作ID不能换要求复用；服务端校验。
- 不得跳过拆解直接生成剧本；拆解任务已提交但未完成时，提示完成后重开报告再做剧本。

## 0. 版式保持原样（2026-11-11 用户再次确认）

- **沿用原报告版式，不得改版**：保留原表格的列、顺序、行结构（编号/作品ID/封面/账号/主题/发布/评论/点赞）与原有说明。
- 只允许两类增量：①顶部加“总体分析与建议”；②每条加**一句简短**的“入选原因”。
- 不改成逐条块状、不重排表格、不删列、不把 50 条拆成 50 个章节。
- 入选原因放在表格末尾新增一列“入选原因（简短）”，每行一句话，约 40–60 字；如必须保留原表格宽度，可另加“入选原因速查”小节按编号列一句，但不得替换原表格。

## 1. 报告顶部增加总体分析与建议

报告开头先给（在 50 条明细之前）：

1. **总体分析**：本批 50 条的共同规律——题材分布、常见钩子/结构、评论区主要诉求与反对意见、可迁移到本地全屋定制/整装/设计的机制、哪些是行业特有、哪些是跨行业可借鉴。
2. **可执行建议**：下轮可优先尝试的方向（含具体选题/开头/结构建议）、不建议照搬的点、需要进一步深拆验证的项；建议必须基于本批实际数据，不承诺流量或获客效果。
3. **可信度与缺口**：明确哪些结论来自显示值/抽样、哪些未观看视频、哪些未核实。

## 2. 每条参考视频增加简短“入选原因”

- 在原表每行（或末尾列）用**一句话**写清：分类配额、评论/点赞依据（附显示值）、窗口依据、可迁移机制；不展开成长段。
- 原因必须可从已有数据复核，不得编造评论、点赞、发布时间或机制；数据缺失写“显示值缺失/待核”。
- 不因“入选原因”改写原筛选结果；原批次窗口、配额、旧事实不变。

## 3. 格式与边界

- 报告仍以 Markdown 交付；顶部分析与建议用可读的短段落/要点，避免空泛。
- 不得把候选写成已验收；不得写“已证实投流/限流”等推断。
- 不因为补原因而重新采集整批；复用本批已有证据，必要时标注缺口。
- 与[情报报告要求](<情报报告要求-20261111.md>)一致的表达原则：标题即结论、结论有依据、建议可执行。
