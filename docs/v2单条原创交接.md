# v2单条原创交接与校验

本支持落实已确认的“快采候选、选中后深拆”流程。只验收用户所选单条，不改变原v1批次、配额、窗口或历史未通过状态；不是新采集框架。当前适配已有benchmark/home补核证据格式，非家居72h另需相应适配，不自动套用。

## 交接门槛

总管明确记录用户选片和创作授权；会话2补核达可供原创参考、评论证据及来源日期合格；总管轻量验收认可并列明事实边界。视觉抽样不冒称连续全片观看，未核音频和现场工程参数不变成事实。

**2026-11-11新增强制项**：所有深拆作品必须取得豆包逐字稿并纳入分析。新交接必须包含该作品的 `doubao-copy-raw.md`、`doubao-copy-meta.json`、`doubao-copy-reviewed.md` 及分析引用（见[豆包文案提取规则](<豆包文案提取规则-20261111.md>)）；未取得（或只有摘要/无法访问）时不得验收通过、不得生成新交接。规则生效前封存的 B10-20261109-v1 属历史例外，不改写、不回溯。

[管理校验器](<../scripts/selected_handoff.py>)检查所选ID、原冻结窗口、对标确认、评论样本、封面/代表图/密集帧实际文件及SHA256、生产方自查和总管验收。生成独立新目录内的selection.json、handoff.json与最后写入的seal.json，拒绝覆盖已有目录。源文件或交接变化会拒绝ready；任务指令另外固定handoff的SHA256，不能靠重算seal静默换内容。

handoff内冻结：用户确认、业务档案、生产方的主题/方案摘要/机制/评论需求与边界、总管验收、源证据哈希清单。**深拆分析必须包含并引用豆包逐字稿（AI辅助，未经真人审核）**；handoff 仍不把整段逐字稿当新稿台词模板，只引用核验后的钩子/机制/CTA要点并标来源路径与哈希。原片表达和字幕不是新稿台词模板。物理文件仍可被外部编辑，因此这里的不可变性为“拒绝覆盖＋哈希锚定＋变更即阻断”，不声称文件系统绝对不可写。

## 会话3开工

收到总管的具体交接目录及SHA256后，运行：

```powershell
python scripts/selected_handoff.py status handoffs/B10-20261109-v1 --expected-hash e293d5a1ae974640f9449dd08ed141373899cfdf61b6f1e14be12135900bdd4b
```

须同时返回valid=true、delivery_complete=true、handoff=ready_for_session3，且scope=selected_reference_only、video_ids与用户选中一致。这三个字段只表示当前所选单条通过v2交接，不表示原50候选全部通过。对该交接不再要求旧v1的整批CLI返回ready；旧v1任务仍使用旧流程。

读取交接目录中的selection.json和handoff.json，使用payload.reference、payload.manager_review、payload.business_profile。不得改上游文件，不得直接重写seal修复失败；若失败回报总管，保留版本后重新验收。只制作明确原创草稿，不拍摄发布。
