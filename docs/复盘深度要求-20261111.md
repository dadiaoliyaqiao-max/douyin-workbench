# 复盘深度要求（2026-11-11 用户确认）

用户指出复盘“过于表面、不够深入”，并要求增加三类结合：①结合对标账号情况；②结合参考视频情况；③结合情报。本要求适用于会话4的所有复盘（基线、增量、专题）。

## 1. 深度标准（必须做到，不只是罗列指标）

1. **逐条诊断**：对观察窗口内的每条作品（含置顶/近期/新发布）给出：题材、钩子、开头 3 秒做法、结构、时长、评论区主要诉求/反对意见、播放与完播表现；解释“为什么可能是这样”，明确标为假设而非因果。
2. **供需对照**：把自有内容与观众评论诉求对照，指出“观众在问什么、我们讲了什么、缺了什么”。
3. **机制归因**：对表现好/差的作品，给出可检验的机制假设（钩子类型、信息密度、结尾 CTA、封面标题、时长、发布时间等），并列出需要什么数据才能验证。
4. **可执行实验**：2–4 个下一轮实验，每个写清变量、对照、观察指标、观察窗口、样本量限制与失败条件；不承诺流量或成交。
5. **证据与缺口**：所有结论标注来源（数据文件、观察时间、窗口、分母）；无分母不算比例，未知不是 0；小样本不推断限流/因果。

## 2. 结合对标账号（会话1）

- 读取会话1最新分析（`research/benchmarks/<analysis_id>/`：`videos.json`、`comments.json`、`sync-manifest.json`、`report.md` 与 `data/benchmarks.json`）。
- 对照内容：对标账号最近新增视频的题材选择、钩子/结构、更新频率、评论诉求；我方账号在同样维度上的差距与机会。
- 产出：**对标对照表**（维度 × 对标做法 × 我方现状 × 差距/可借鉴点），以及“可迁移 3 条 + 不可照搬 3 条”。
- 不得重复会话1的分析工作；引用其结论并标路径。

## 3. 结合参考视频（会话2）

- 读取最新参考批次报告（`batches/<批次>/quick-pick-v3.md`/结构化数据）与已发布的原创脚本映射（`scripts-output/<批次>/publication-map.json`）。
- 对照内容：批次里的可迁移机制（钩子、叙事、评论回应、结尾动作）有哪些已用在自家作品；用了的与没用的在表现上的差异（只描述相关，不推断因果）。
- 产出：**机制采用对照**（机制 × 是否采用 × 对应作品 × 表现），并给下轮 1–2 个可测试机制。
- 没有发布映射时明确写“无法关联”，不编造。

## 4. 结合情报（会话5）

- 读取最新情报报告（`research/platform-intelligence/<研究ID>/report.md` 与 `sources.json`）。
- 对照内容：①合规风险：自家内容/计划是否符合最新官方规则（如虚假人设、AI 数字人、摆拍、资质表述等）；②机会：搜索/同城/新功能中可合规尝试的方向；③待验证：情报里的假设哪些与本账号数据相关。
- 产出：**情报对照**（条目 × 对本次复盘的影响 × 建议动作/不动作），并注明情报日期与适用范围。
- 情报未涉及或未核实的，标“未覆盖/未核实”，不把假设当规则。

## 5. 报告结构（固定）

1. 顶部：**总体诊断**（3–5 条，最重要的判断与依据）。
2. 数据与证据（窗口、口径、样本、缺口）。
3. 逐条作品诊断（深度要求第 1 条）。
4. 对标账号对照（第 2 节）。
5. 参考视频机制对照（第 3 节）。
6. 情报合规与机会对照（第 4 节）。
7. 归因假设与下轮实验（第 1 节第 3–4 条）。
8. 缺口与未验证。

## 6. 边界

- 仍只读；发布、互动、投流、支付等外部操作需另行授权。
- 不得读客户身份/私信全文；匿名必要信息即可。
- 不因本次深度要求改写旧复盘/旧指标；新增版本或新目录，保留历史。
- 引用会话1/2/5 的数据只读，不改其他模块文件。
