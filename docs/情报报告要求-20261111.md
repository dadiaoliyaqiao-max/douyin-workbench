# 情报报告要求（2026-11-11 用户确认）

适用：会话5「情报」模块的输出报告（`research/platform-intelligence/<研究ID>/report.md` 及其结构化文件）。

## 1. 标题必须是内容的关键提炼

- 报告主标题、每个章节标题、每条情报标题，都要让人**只看标题就知道要说什么**：对象＋变化/结论（必要时带日期）。
- 禁止空泛标题，如“其他动态”“补充观察”“新规汇总”“若干发现”。
- 示例：
  - 好：“抖音10月处置2.6万虚假人设账号，‘AI数字人业主’在打击范围”
  - 差：“关于虚假人设治理的公告”
  - 好：“AI工坊内测对家装可用，但内测资格与分发规则未知”
  - 差：“AI工坊观察”
- 标题不得超出证据：未核实要写“未核实/待确认”；公示期要写“公示中，非已生效”。

## 2. 每个内容必须有引用源链接

- 每条情报、每个事实性判断都要给可点击来源链接；优先官方原文，其次权威媒体转述，并标明类型。
- 记录：链接、发布日期（可精确到日）、访问时间（Asia/Shanghai）、是否读到正文、来源类型（官方原文/官方转载/媒体转述/单案例/未核实线索）。
- 读不到原文时：给索引/转载链接并标“未取得原文”，不得用无来源结论凑数。
- 同一结论多个来源时给主链接＋辅证；不得编造链接或日期。

## 3. 报告顶部放总体分析与建议

报告结构固定为：

1. **顶部：总体分析**——本期最重要的 3 件事、对本地全屋定制/整装/全屋设计业务的影响（机会/风险各列）、可信度与不确定项。
2. **顶部：可执行建议**——本月可做（含具体动作与验证指标）、本月不要做（风险项）、待验证/待观察；建议必须对应到具体证据链接，不承诺流量或获客效果。
3. **条目明细**——每条：结论式标题、事实摘要、来源链接、适用对象、生效/公示状态、对本地业务的影响、局限与未核实项。
4. **缺口与未验证**——写清哪些方向没查到、哪些说法无法确认。

## 4. 边界

- 官方原文、媒体转述、单案例观察、行业假设分开标注；公示/征求意见不等于生效。
- 广告/电商/直播规则不自动外推到全部短视频账号；不把广告产品当自然流量机制。
- 不编造案例、数据、日期或链接；不把单案例当算法变化证据。
- 仍只读、不发布、不互动、不投流、不安装监测、不设定时。
